# 澄数 · 内网报表查询平台

面向 Windows 内网服务器的可运行平台。Node.js 24 + SQL Server 驱动，平台配置和审计保存在本机 SQLite 中，业务数据保留在 SQL Server。

## 启动

当前工作目录已完成依赖安装和本机初始化，初始登录信息见同目录 `首次登录.txt`。本机服务地址为 `http://127.0.0.1:3080`。以下步骤适用于另行部署到新服务器。

1. 安装 Node.js 24 LTS。
2. 在项目目录执行 `npm ci`。
3. 执行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`，设置管理员初始密码。
4. 执行 `npm start`，浏览器访问 `http://127.0.0.1:3080`。
5. 使用 `admin` 和设置的密码登录，选择默认账套。

首次启动创建默认账套（组织 ID 为 1）和管理员。没有内置通用密码。首次初始化后可从 `.env` 删除 ADMIN_PASSWORD，已有账号密码保存在数据库哈希中。

## 配置顺序

1. 数据源管理：配置服务器、端口、数据库、只读账号和密码，点击测试连接。可维护多个连接。
2. 账套管理：配置不同账套及其组织 ID。报表的数据源决定数据库，账套决定该数据库中的组织范围。
3. 报表中心 → 新建报表：选择数据源、维护 SELECT、组织字段、显示字段与中文名称。
4. 角色与权限：针对每张报表分别授予查看、查询、导出、配置 SQL / 字段。
5. 用户管理：创建账号，指定一个或多个角色及可登录账套。多个角色权限取并集。
6. 查询审计：按北京时间查看每日、每用户、每报表、每账套查询次数、导出次数和失败次数，以及操作明细。

## SQL 示例

```sql
SELECT OrgId, OrderNo, CustomerName, OrderDate, Amount
FROM dbo.SalesOrders
```

组织字段填写 `OrgId`。显示字段可配置 `OrderNo → 单据编号`、`CustomerName → 客户名称`、`OrderDate → 单据日期`、`Amount → 金额`。组织字段必须出现在 SQL 返回列中，可不配置为显示字段。

平台将 SQL 包装成派生表，在外层添加 `OrgId = @org`，组织 ID 来自服务端登录账套，不接受浏览器覆盖。筛选字段必须来自报表配置，筛选值通过驱动参数传入。支持每个配置字段的包含、等于、不等于、大于、小于、范围组合、为空查询。多个条件为 AND；同一字段加“大于等于”和“小于等于”即可指定日期或金额范围。日期建议输入 ISO 格式。

SQL 只支持可作为派生表的单条 SELECT。不支持存储过程、临时表、CTE、多语句、注释和末尾分号，ORDER BY 请移除。字段名限英文、数字、下划线，通过显示名称设置中文表头。SQL 管理权限只应授予可信管理员；其拥有读取配置数据源的能力，能改写组织字段表达式，因此 SQL 管理员属于可信边界。对严格隔离场景，应同时在 SQL Server 配置数据库级行安全或受控视图。

**必须使用数据库只读账号**：仅给报表所需表或视图授予 SELECT，不授予写入、DDL、存储过程执行和服务器管理权限。平台 SQL 检查是附加防护，不替代数据库权限。

## 部署到 Windows 内网

- 将完整目录部署到服务器，保留 package-lock.json，通过 `npm ci --omit=dev` 安装依赖。
- 使用 Windows 任务计划程序启动 Node（启动参数 `server/index.mjs`，起始目录设为项目目录），设为系统启动时运行、失败时重启，使用专用低权限服务账号。
- 推荐 IIS 反向代理到 `127.0.0.1:3080`，在 IIS 配置内网 HTTPS，并将 `.env` 的 `COOKIE_SECURE=true`。如直接监听内网，可修改 HOST，但正式环境应通过 HTTPS 登录。
- 仅允许服务账号读取 `.env` 和 `data` 目录，不应通过 IIS 静态站点暴露项目根目录。Node 仅提供 dist 中的四个静态资源。
- 防火墙只开放所需内网入口与 SQL Server 出站连接。
- `.env` 中 ENCRYPTION_KEY 为数据库连接密码加密密钥，必须单独安全备份，不能随意更换。
- 停止服务后备份 `data/platform.sqlite` 及 `.env`，恢复时一并恢复。运行期间应使用 SQLite 备份机制，不要只复制主文件而忽略 WAL。

## 当前实现与边界

- 服务端逐次检查用户启用状态、角色权限与账套权限；修改用户会撤销其全部会话。
- 密码使用随机盐 scrypt；数据库密码使用 AES-256-GCM；会话有效期 8 小时、HttpOnly、SameSite=Strict。
- 登录失败按来源地址限制为 15 分钟最多 10 次。反向代理环境不信任任意 X-Forwarded-For，可能对代理后用户共享限流，可按部署情况扩展可信代理配置。
- 查询最多展示 500 行；导出最多 10000 行，超限明确拒绝并提示缩小范围。CSV 使用 UTF-8 BOM，可用 Excel 打开，并防护公式注入。
- 单次 SQL 超时 30 秒。当前为单机部署；大规模并发、任务队列、异步大文件导出、分页排序、MFA、SSO、密码找回及审计归档尚未实现。
- 支持管理员创建用户、停用用户、重置密码、分配角色与账套；不包含邮件注册或自动找回密码。
- 尚未连接您的真实 SQL Server。上线前需使用实际表结构验证 SQL、组织归属、日期类型、证书和只读数据库权限。

## 验证

`npm run check` 检查语法，`npm test` 验证密码、加密、SQL 防护、组织隔离参数化，以及真实 HTTP 登录、账套授权、配置保存、未授权访问拒绝和注销。接口测试使用独立临时数据库，不连接真实 SQL Server。
